# Mind Kernel 開発・運用の手引き (Kernel Rules)

このリポジトリ（Mind Kernel）を扱うAIエージェントおよびユーザーが守るべき共通のルールです。

## 1. プライバシーと公開ポリシー (CRITICAL)

- **パブリック公開が前提**: このリポジトリはテンプレートとして一般公開されることを前提としていますが、**利用者が実際に自身のデータを入力して運用する際は「Privateリポジトリ」として運用することを強く推奨してください。**
- **固有名詞の排除**: 人名、会社名、具体的なプロジェクト名などの固有名詞は直接記述せず、「A社」「プロジェクトリーダー」などの抽象化された表現に置き換えてください。
- **機密情報の禁止**: パスワード、APIキー、住所、電話番号などの機密情報は、絶対にファイル内に直接書き込まないでください。
- **Git履歴の意識**: 一度コミットした内容は履歴に残ります。個人情報を誤ってコミットした場合は、単に削除するだけでなく、履歴の抹消（`git filter-repo` 等）を検討してください。

## 2. モジュール構造の維持

情報は必ず以下の定義に従って分類し、適切なファイルに保存してください。

- **`identity.json`**: あなたの「 Nature（不変の核）」。価値観や強みなど。
- **`backlog.json`**: 「Active Issues（動的な状態）」。現在進行形の課題や実験。
- **`patterns.json`**: 「Learn（再現性のある知恵）」。獲得した思考パターン。
- **`meta.json`**: 「System」。システムの設計思想やAIへの指示。

## 3. 実装のベストプラクティス

- **TDDの尊重**: 新しい機能やスクリプトを追加する際は、テストコードを先に書くか、仕様を明確にしてから実装してください。
- **JSONの整合性**: JSONを更新する際は、既存のスキーマを壊さないように注意してください。
- **自動化**: `scripts/` 配下のスクリプトは、GitHub Actions での動作を想定して設計してください。環境変数は GitHub Secrets から取得するようにします。

## 4. エージェントへの指示

AIエージェントは、本リポジトリの内容を「ユーザーの外部脳」として扱い、常にユーザー固有のコンテキストに基づいた最適な提案を行ってください。不確かな情報は「仮説」として提示し、対話を通じて `backlog` や `patterns` を更新する提案を行ってください。
